# Mcqueen-uma-auto — Refactor Plan

**Date:** 2026-07-22
**Branch:** `refa` (rebased onto `unity_dev` @ `cf09239` — `main` was 81 commits behind and lacked `backend/app`)
**Author intent:** Whole-project refactor, phased **backend → engine → polish**.

## Scope decisions (locked)

| Decision | Choice |
|---|---|
| Priority | **Backend monolith first**, then engine internals, then polish |
| Target backend architecture | **`backend/app/routers/<domain>/{controllers,services,schemas}`** — finish this pattern, delete the abandoned `uma_app/routes/*` stubs |
| Behavior policy | **Cleanup allowed** — bug fixes and modernization permitted, but committed *separately* from pure structural moves |

## Thesis

Strangle the `uma_app/legacy.py` monolith (3,737 lines, 58 routes, all module-global state) into the newer `backend/app/routers` domain pattern that is already ~3/17 built. Then decompose the three engine god-files. Every step is a small atomic commit that keeps the test suites green. **No** SHA-lease / bundle / secret-scan ceremony — that machinery is what made the previous attempt unusable.

## 1. Guiding principles

### 1.1 Git & commit discipline
- All work happens on `refa`. Never push without explicit user permission.
- **One seam per commit.** A commit either *moves* code (no behavior change) or *changes* behavior (bug fix / cleanup) — never both. This keeps review and `git revert` clean.
- Commit message states: what moved/changed, why behavior is preserved (or the intentional change), and which checks passed.
- Rollback is `git revert <commit>`, not broad reset.

### 1.2 Verification ladder
Run the lowest applicable rungs before every commit; higher rungs at phase boundaries.

| Rung | Command (PowerShell, repo root) | When |
|---|---|---|
| **L0** compile + hygiene | `& .\.venv\Scripts\python.exe -m compileall main.py uma_app uma_api career_bot backend` · `git diff --check` | every commit |
| **L1** focused tests | the specific `pytest ...` / `npm --prefix frontend run test -- <name>` for the touched area | every commit |
| **L2** full Python suite | `& .\.venv\Scripts\python.exe -m pytest -q` | every commit touching Python |
| **L3** frontend | `npm --prefix frontend run test` · `run build` · `run lint` | every commit touching `frontend/` |
| **L4** API integration | FastAPI `TestClient` route-contract suite (built in Phase 0) | any route/app/session change |
| **L5** live-game smoke | manual, operator-run, isolated runtime dir, disposable account | only at auth/session/runner boundaries + once pre-merge |

**L5 never gates a pure structural move.** A structural move is verified by L0–L4 + the route-contract snapshot being byte-identical.

### 1.3 Safety (this bot drives a live account)
- Secrets and machine-local runtime **never** enter git: `uma_runtime/`, `master.mdb`, auth files, Steam refresh tokens, Discord webhooks, reports, traces, captures, `node_modules/`, `frontend/dist/`, `.venv/`.
- Preserve **account-isolation** invariants whenever touching session/auth/accounts: account A's state, credentials, or responses must never reach account B.
- Preserve **runner-lifecycle** invariants: no run-loop thread survives stop/logout/delete; no duplicate live API action.
- Wire-format invariants are frozen: SID hash chain, AES/MsgPack framing, and the event-choice zero-based↔one-based conversion do not change.

## 2. Current-state map (why this plan exists)

- **`uma_app/legacy.py` (3,737 lines)** creates the FastAPI `app`, owns all module-level mutable state (`chara_map`, `support_map`, succession/win-saddle maps + `loaded` flags, `PresetStore`/`RacePresetStore`/`BotConfigStore`, rank-point locks), runs startup data loading, serves static assets, and defines **58 routes** via `@app.*`.
- **Two half-built migration targets exist:**
  - `uma_app/routes/*` — 7 six-line stub files, never wired. **To be deleted.**
  - `uma_app/career.py`, `auth.py`, `system.py`, `storage.py`, `deps.py`, `schemas.py` — dead re-export facades from an *earlier* abandoned split (`schemas.py` even fails to import). Also to be deleted. (Surfaced by the review — §5.)
  - `backend/app/routers/*` — the newer `<domain>/{controllers,services,schemas}` pattern. **3 domains “done”** (`settings`, `master_datas`, `bot_configs`) — but the reference `master_datas` services carry real runtime bugs (wrong arity / missing `self`) that break `/api/master-data/*` today (§5, Phase 2). **14 empty 0-byte stubs** (`accounts, auth, careers, sessions, steams, selections, races, presets, parents, events, debugs, images, assets, others`).
- **Dead duplicate routes:** the 3 migrated domains' old copies remain in `legacy.py` as **commented-out** blocks (≈ lines 1400–1465) — dead, to be deleted. The raw `@app.*` grep behind the 58-route count in §4 matches these commented decorators too, so Phase 0's L4 pass sets the authoritative *live* inventory.
- **Engine god-files:** `career_bot/runner.py` (2,305), `career_bot/items.py` (1,911), `uma_api/client.py` (1,428).
- **Verification gaps:** engine is heavily tested (~10.7k LOC across `tests/`), but the **web layer has no tests**, there is **no `.venv`**, and **test deps are unpinned** (`pytest`/`httpx` absent from `requirements.txt`).
- **Git cruft (✅ cleaned 2026-07-22):** the previous attempt had left **2,504 `worktree-agent-*` branches**, **1,572 linked worktrees**, and 4 `refactor/*`/`phase-*` branches — all removed; repo is down to 5 real branches + the main worktree.

`create_app()` today is a 13-line shim that returns the legacy app. The end state makes it the *real* assembler.

## 3. Phases

### Phase 0 — Foundation & safety net
**Goal:** a reproducible green baseline and a net under the untested web layer, before any code moves.

1. **Environment:** create `.venv` (Python 3.11), add `requirements-dev.txt` pinning `pytest` + `httpx` (needed for `TestClient`). Document setup in `DEPENDENCIES.md`.
2. **Green baseline:** run L2 (`pytest`) and L3 (frontend test/build/lint); record results. Fix only environment/collection errors, not product bugs.
3. **Web-layer characterization (L4):** add `tests/test_api_routes.py` — a FastAPI `TestClient` suite hitting the 58 routes with fake sessions/clients, asserting status + response shape + account-isolation on the account-scoped ones. This is the snapshot that Phase 1–2 must not break.
4. **Git hygiene — ✅ DONE (2026-07-22):** pruned the 2,504 `worktree-agent-*` branches + 1,572 worktrees + `refactor/*`·`phase-*` leftovers; deleted the untracked `refactor-plans/`. Repo clean (5 real branches, 1 worktree).

**Exit:** L2 + L3 green and recorded; L4 route-contract suite passes; `git worktree list` and `git branch` are clean.

### Phase 1 — Deconstruct the monolith core
**Goal:** separate *app assembly* and *shared state* from *route handlers*, so routes can then move cleanly.

1. Make `uma_app/app.py:create_app()` a real factory: build `FastAPI`, register `NormalRouter`, mount startup/lifespan, return it. `main.py` already calls it.
2. Extract module-global state from `legacy.py` into a cohesive context module (e.g. `backend/app/state.py` or `uma_app/context.py` extended): the master-data maps + `loaded` flags, the three stores, and the rank-point locks. Provide accessors so route handlers stop reading module globals directly.
3. Move startup data loading (chara/support/succession/win-saddle) into a `lifespan` handler or dedicated `startup` module.
4. Keep `legacy.py` importing from the new modules so routes still work mid-phase.

**Exit:** `legacy.py` contains only route functions; app assembly + shared state live in their own modules; L2 + L4 green; route snapshot unchanged.

### Phase 2 — Strangle routes into `backend/app/routers`
**Goal:** move all 58 routes out of `legacy.py` into domain routers, then delete `legacy.py`.

Per domain: create/fill `<domain>/{controllers,services,schemas}` following the `settings` domain as the reference pattern → register the router in `backend/app/routers/__init__.py` → **delete** the `@app.*` originals from `legacy.py` → verify L4 snapshot byte-identical. One domain per commit. Business logic goes to `services/`, request/response models to `schemas/`, thin handlers to `controllers/`.

> **Do this first:** fix the `master_datas` reference-domain runtime bugs (`loader.py`, `synthesize_data.py` — §5, Phase 2) and standardize the domains' dependency-acquisition pattern **before** copying the pattern into 14 more domains — the reference must be correct first.

Order (low → high risk) — see the full inventory in §4:

1. **Dedupe already-migrated** — delete shadowed `settings` (5), `master-data` (3) legacy copies; confirm `bot_configs` has none.
2. **Static / assets / images / debug** — routes 50–58 (file serving + SPA catch-all; catch-all registers **last**).
3. **presets + race-presets** — routes 9–16.
4. **skills + events** — routes 17–22.
5. **selection + parents** — routes 28–31.
6. **accounts** — routes 33–36 (import/export = persistence; guard partial writes + isolation).
7. **auth / session / steam** — routes 23–27, 32, 45–46 (**credentials & session lifecycle — highest care**).
8. **career** — routes 37–44, 47–49 (**runner lifecycle & live dispatch — highest risk**).

Then: delete `uma_app/routes/*` stubs; reduce `legacy.py` to nothing and remove it; confirm `create_app()` builds the entire app from `backend/app`.

**Exit:** `legacy.py` deleted; all 58 routes served from domain routers; L4 snapshot unchanged across the whole phase; L2 + L3 green; one L5 auth/session + one L5 career smoke pass (or recorded skip).

### Phase 3 — Engine internals
**Goal:** decompose the three god-files, backed by the existing heavy test suites.

- `career_bot/runner.py` (2,305) → split the career **state machine**, **recovery**, **reporting/finalization**, and **API-action dispatch** into focused modules. Freeze the runner snapshot contract first (it feeds the frontend).
- `career_bot/items.py` (1,911) → decompose shop/item logic by concern (catalog, selection/deck-match, purchase/use).
- `uma_api/client.py` (1,428) → separate **transport**, **crypto (AES)**, **MsgPack framing**, and **SID hash chain**.

**Exit:** no engine file ≫ ~800 lines (soft target); `test_skills`, `test_items`, `test_game_service`, `test_runner_*`, `test_*_recovery` all green; L5 career smoke unchanged.

### Phase 4 — Polish
**Goal:** finish the long tail (cleanup-allowed shines here).

- **Frontend:** split `frontend/src/api/types.ts` (540) by domain; light dedup. (Frontend is already modular + tested — light touch.)
- **scripts/:** organize the RE/sniffer tooling (`sniff_*`, `scrape_*`, `probe_*`, `hook_*`), dedupe shared capture code, label clearly as dev-tooling not app runtime.
- **Dead code:** remove shadowed/dead paths, unused stubs, obsolete `public/` fallback if `frontend/dist` is now canonical.
- **Deps:** pin `msgpack` + `lz4`; reconcile `pycryptodome` version vs `DEPENDENCIES.md`; finalize `requirements-dev.txt`.
- **Optional:** mypy pass; tighten `.flake8`.

**Exit:** clean deps + lint; L2 + L3 green.

> From a 12-agent code review (Sonnet) of the rebased `refa` tree — **169 findings**, highest-value shown, each tagged to a phase below. Fixes here follow §1.1: behaviour changes (including all API renames) commit **separately** from pure moves.

Twelve reviewer passes converge on the same handful of systemic problems, all of which map cleanly onto the phases already defined above. First, **`uma_app/legacy.py` and its "split" siblings are worse than the plan's current-state map assumes**: `uma_app/career.py`/`auth.py`/`system.py`/`storage.py`/`deps.py` are a fully dead, undocumented earlier split attempt (one of them, `schemas.py`, doesn't even import), and `start_career_from_request` is a 380-line god-function driven by fragile string-matched error codes. Second, **the three "reference" backend domains that Phase 2 is supposed to copy are themselves inconsistent and, in `master_datas`, outright broken** — `MasterDataLoader.load_master_data`/`get_existing_tables` and `SynthesizeMasterData.factor_category`/`synthesize_public_race_data` have wrong-arity/missing-`self` bugs that make `/api/master-data/generate` and `/api/master-data/path` throw or silently no-op today; fixing this before more domains copy the pattern is the single highest-leverage Phase 2 item. Third, **the engine layer (`career_bot/items.py`, `uma_api/client.py`, `career_bot/master_data.py`, `career_bot/skills.py`, `career_bot/scenarios/**`) is a set of large, untyped god-classes/functions with recurring duplication**: parallel MANT/Unity Cup scoring engines, triplicated turn-constant ladders, three parallel item-catalog keying schemes, a 250-line transport function in `UmaClient._call_locked` that raises untyped exceptions a downstream `getattr`-based handler can never actually match, and a scattering of bare `except Exception: pass` swallows with no logging across `items.py`, `skills.py`, `events.py`, `master_data.py`, and `notify.py`. Fourth, **the HTTP surface itself has no naming discipline** — mixed snake_case/kebab-case paths, `POST .../delete` instead of `DELETE`, two copy-pasted preset route families, camelCase leaking into an otherwise snake_case JSON API, and inconsistent response envelopes — which is broken out into its own subsection below since these changes are behavior-affecting and cross frontend/backend. Frontend is the one clean area, with only small polish items. Highest-ROI order: fix the Phase 2 `master_datas` runtime bugs and reference-domain inconsistencies first (they block everything downstream), delete the dead `uma_app/*` split modules and dead engine code opportunistically during the same moves, then tackle the god-function/duplication debt in Phase 3 while the heavy engine test suites are green.

### API naming convention

The route surface (58 legacy.py routes + the migrated `master_datas`/`settings`/`bot_configs` domains, cross-checked against every `frontend/src/api/*.ts` consumer) has no single naming discipline today: path segments mix snake_case and kebab-case, deletes are modeled two incompatible ways, two copy-pasted preset route families exist, camelCase leaks into an otherwise snake_case JSON API, and response envelopes are inconsistent on the error path. **These renames are behavior-affecting API-contract changes** — per this plan's move-vs-change rule (§1.1), they must be committed separately from the pure Phase 2 route *moves*, coordinated with the corresponding `frontend/src/api/*.ts` call-site updates in the same commit, and covered by the Phase 0 route-contract (L4) suite before/after each rename.

**Agreed rules:**
1. All paths live under `/api/`, kebab-case for every multi-word path segment — no snake_case (`save_races`, `burn_clocks`, `start_state`), no camelCase.
2. Every name-keyed resource (presets, race-presets, parents, accounts) is deleted via `DELETE /api/{resource}/{id-or-name}` — never `POST /api/{resource}/delete`.
3. JSON body/response keys are snake_case everywhere, no exceptions — retire `friendExcludeIds`/`rentalQuota`/`friendsLoaded`.
4. Every response is `{"success": true, ...}` on success and `{"success": false, "detail": "<human message>"}` on failure, plus a separate `error_code` for any machine-checkable state (never overload `detail` with a sentinel like `"locked"`).
5. All auth-adjacent endpoints (login, logout, session, session/refresh, steam/qr/*, auth/recapture*) live under `/api/auth/*`.
6. The two copy-pasted preset systems (`/api/presets/*`, `/api/race-presets/*`) collapse into one `/api/presets` family disambiguated by a `kind` discriminator instead of a wholly separate route tree.
7. List-result key names use one consistent verb for "removed" across the whole API — standardize on `deleted` (not `removed`).

## 11. Package layout — should `uma_app`/`uma_api` move into `backend/`? (assessed 2026-07-23)

**Current dependency graph** (arrows = "imports", verified by import-edge grep):
```
frontend
   │
backend/app/routers  ⇄  uma_app (context, create_app, web helpers)      ← mutual cycle
   │                        │                                             (lazy imports work around it)
   └───────────┬────────────┘
               ▼
        career_bot  ⇄  uma_api                                           ← mutual cycle = ONE engine layer
```
Measured edges: `career_bot → uma_app` = **0** (the engine never imports the web glue); `uma_api → backend` = 0, `uma_api → uma_app` = 0 (engine client depends on nothing web); `uma_api ⇄ career_bot` mutually coupled (`client.py`↔`delay`/`client_version`/`update_guard`, `game_service`↔`master_data`/`master_updater`, `session`↔`runner`); `backend → uma_app` = 19 files + `uma_app/app.py → backend.app.routers` = 1 (the web cycle); `backend → uma_api` = 20, `backend → career_bot` = 6.

**Roles:** `uma_api` = the game-server client/session (transport, crypto, SID) — *engine infrastructure*, peer of `career_bot`. `career_bot` = the bot decision engine. `uma_app` = FastAPI assembly (`app.py:create_app`) + runtime state (`context.py`) + web helpers (`rank_point`/`career_selection`/`account_status`/`account_store`/`preset_runtime`/`gameproc`/`jsonstore`/`cli`) — *web-app layer*, the other half of `backend`.

### Verdict
- **`uma_api` → `backend/`: NO (do not).** `uma_api` is mutually coupled with `career_bot`; moving it under `backend/` would make the headless bot engine import from the web package — a dependency inversion that destroys the engine↔web separation and the ability to run/reason about the engine without FastAPI. `uma_api` belongs at engine level, a **peer** of `career_bot`, not a child of `backend`.
- **`uma_app` → `backend/`: OPTIONAL, defensible tidiness — NOT necessary.** `uma_app` is web-only (`career_bot` doesn't touch it) and already cyclically bound to `backend`. Folding it in would consolidate the web app into one package **and can eliminate the `backend↔uma_app` cycle** that currently forces the lazy in-method imports (stages 6–8). The current 2-package split is already cleanly layered and works; this is polish, not a correctness need.

### Phase 6 (optional) — fold `uma_app` into `backend/`, keep the engine peers
Only if the tidiness/cycle-removal is judged worth the churn. Sketch:
1. Move `uma_app/context.py` + the web helpers (`rank_point`, `career_selection`, `account_status`, `account_store`, `preset_runtime`, `jsonstore`, `gameproc`) into `backend/app/` (e.g. `backend/app/context.py`, `backend/app/domain/*`), and `create_app`/`cli` into `backend/app/app.py`/`backend/app/cli.py`. Order the package so `context`/helpers sit *below* routers → the cycle disappears and the lazy imports can become normal top-level imports.
2. Repoint ~50 import sites: `backend → uma_app.*` (19 files), `main.py`, and the test suite (`import uma_app.X` → `backend.app.X`). Same patch-where-used discipline as §8b stage 7; STATE names (`rank_point.chara_map` etc.) stay call-time module-attribute access.
3. Leave `uma_api` + `career_bot` exactly where they are (engine peers). Optional cosmetic nicety: group them under an `engine/` namespace — but that's a second large move touching the `uma_api⇄career_bot` cycle for pure aesthetics; low priority, likely skip.

**Cost/risk:** large, behavior-affecting-adjacent move over isolation-critical `context`/`session`/startup wiring (~50 sites) — same risk class as the legacy split. **Gate:** pytest 677/6 + vitest + build + flake8/mypy after each slice, and the §9 operator live-smoke before trusting it. **Do it (if at all) as its own phase after the live-smoke, one cohesive move per commit — never blind.** Recommendation: **skip unless** a concrete pain (the lazy-import friction, or onboarding confusion from two web packages) actually bites; the layering is already correct.
